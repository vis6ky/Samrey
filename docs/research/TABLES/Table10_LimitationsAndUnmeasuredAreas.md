# Table 10: Architectural Limitations and Unmeasured Research Areas

| System Area | Explicit Architectural Constraint | Mitigation / Workaround | Evaluation Status |
| :--- | :--- | :--- | :--- |
| **Component Variable Closures** | Local variables initialized in the component body do not automatically trigger DOM re-evaluations on mutation unless wrapped in signals. | Compiler emits static diagnostic warnings when unbound local variables are referenced in dynamic JSX nodes. | **Evaluated Internally**; verified in test suite. |
| **AOT Compilation Prerequisite** | Pure ahead-of-time compilation prevents runtime dynamic template compilation via strings (`eval` / `new Function` are strictly prohibited). | Complies with strict CSP (`script-src 'self'`); templates must be pre-compiled via Vite/Rollup plugin. | **Evaluated Internally**; verified in test suite. |
| **In-Place Array/Object Mutation** | Mutating array elements directly (`arr[0] = 5`) does not notify signal subscribers unless re-assigned or wrapped in `createStore()`. | Developers use `createStore()` with Proxy traps or immutable signal updates (`sig.set([...sig.value])`). | **Evaluated Internally**; verified in test suite. |
| **SSR Non-Deterministic Values** | Dynamic values generated during SSR (e.g., `new Date().toISOString()`, `Math.random()`) cause client hydration mismatches if uncoordinated. | Values must be stored in the shared SSR state context (`createSSRContext({ timestamp })`) to ensure client-server parity. | **Evaluated Internally**; verified in test suite. |
| **Large-Scale External Developer Study** | Cognitive overhead, onboarding speed, and syntax ergonomics have not been evaluated across external commercial teams. | The current study relies exclusively on automated benchmark suites and 20 frozen blind challenge evaluations. | **Not Evaluated in the Current Study** |
| **Independent Third-Party Benchmarking** | Formal submission to external third-party benchmarks (such as official web-framework benchmarking consortiums). | Internal benchmarking using standard Krausest-style DOM benchmarks under controlled container conditions. | **Not Evaluated in the Current Study** |
| **Longitudinal Enterprise Telemetry** | Multi-year production stability and memory behavior under real-world enterprise consumer traffic. | Synthetic memory stress testing and owner disposal tree validation (`docs/PERFORMANCE.md`). | **Not Evaluated in the Current Study** |
| **Legacy Browser Support** | Explicit non-support for legacy browsers (Internet Explorer 11 and older JavaScript engines without ES2022 `<template>` support). | Modern evergreen browsers (Chrome 90+, Firefox 90+, Safari 15+, Edge 90+) are fully supported. | **Architectural Decision** |
