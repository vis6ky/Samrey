# Samrey Universal AI Platform Compatibility Matrix & Verification Report

## Executive Summary
This document provides empirical verification evidence demonstrating that **Samrey** is universally usable across modern AI coding environments without manual explanation of the framework.

Unlike traditional frontend frameworks that rely on runtime Virtual DOM reconciliation and component re-execution, Samrey is an independent, compile-time reactive framework with zero Virtual DOM. To ensure that AI coding assistants do not hallucinate React hooks (`useState`, `useEffect`) or Vue directives (`v-if`, `v-for`), the `@samrey/ai` and `@samrey/mcp-server` packages provide a unified multi-agent integration layer.

Empirical verification was conducted against the concrete reference application located at `examples/universal-ai-sample/` using the automated verification suite `tests/universal-ai-usability.test.ts` (41/41 passing assertions across all 5 environments).

## 2. Verification Criteria Definitions & Evidence

### (1) Documentation Discovery
- **Requirement**: The coding assistant must automatically discover authoritative framework instructions upon opening the workspace, without user prompts.
- **Evidence**:
  - Gemini CLI reads `GEMINI.md` at repository root.
  - Claude Code discovers `CLAUDE.md` and connects to `samrey://docs/overview` MCP resource.
  - Cursor automatically evaluates `.cursor/rules/samrey.mdc` on all `.ts, .tsx, .js` files.
  - OpenAI Codex reads `AGENTS.md`.
  - GitHub Copilot ingests `.github/copilot-instructions.md`.

### (2) Correct Framework API Retrieval (Zero Hallucination)
- **Requirement**: When asked for reactivity, state, routing, forms, or HTTP, the AI must retrieve native Samrey APIs and reject foreign idioms.
- **Evidence**:
  - Reactive state queries return `signal`, `computed`, `effect`, `batch` from `@samrey/reactivity`.
  - Zero hallucination of React hooks (`useState`, `useEffect`, `useMemo`, `useCallback`, `useRef`).
  - Zero hallucination of Vue directives (`v-model`, `v-if`, `v-for`).

### (3) Native Samrey Component Generation
- **Requirement**: Components generated by the AI must follow Samrey's compile-time static template hoisting and surgical DOM binding model.
- **Evidence**:
  - Invariant HTML markup is hoisted via `template("...")`.
  - Dynamic properties are bound via surgical micro-binders: `bindText(el, () => count.value)`, `bindAttr(el, 'data-theme', () => theme.value)`.
  - Event listeners are attached with `on(el, 'click', () => count.update(n => n + 1))`.
  - Component functions run **exactly once** during initialization.

### (4) Reactive State Implementation
- **Requirement**: State mutations must obey fine-grained signal graph invariants and array immutability.
- **Evidence**:
  - Signals are updated via `.value = ...`, `.set(...)`, or `.update(fn)`.
  - Array and object signals use immutable reference updates (`tasks.update(arr => [...arr, newTask])`).
  - Batched operations execute in a single microtask flush via `batch(() => { ... })`.

### (5) Routing Implementation
- **Requirement**: Client-side single-page application navigation and route matching without full page reloads.
- **Evidence**:
  - Routes declared with `createRouter(routes, initialPath)`.
  - Components rendered into `RouterOutlet()`.
  - Navigation performed via `Link({ href: '/target', children: 'Text' })` or `router.navigate('/target')`.
  - Parameterized routes (`/users/:id`) and wildcards (`*`) correctly parsed via `matchPath`.

### (6) Successful Compilation
- **Requirement**: Templates must compile cleanly through `@samrey/compiler` AST tokenizer and codegen pipeline without TypeScript errors.
- **Evidence**:
  - `compileTemplate(html)` produces valid `AIRTemplateUnit` hoisting structures and `generatedCode`.
  - Zero compiler errors across standard HTML elements, SVG structures, attributes, and events.
  - Strict typecheck verification (`npx tsc --noEmit`) passes with exit code 0.

### (7) Error Diagnosis & Quick-Fixes
- **Requirement**: Compiler errors and foreign framework anti-patterns must be diagnosed with actionable quick-fixes.
- **Evidence**:
  - `SAMREY-108` (using `<Show>` or `<For>` as HTML template tags) immediately diagnosed with the replacement `Show({ when, children, fallback })`.
  - `SAMREY-101` (unclosed HTML tag) provides exact line and missing closing tag suggestion.
  - React hook imports trigger immediate warning with corresponding `@samrey/reactivity` replacements.

### (8) Production Build
- **Requirement**: Full production bundling produces optimized static assets and server-side rendering artifacts.
- **Evidence**:
  - `vite build` in `examples/universal-ai-sample/` completes in ~230ms:
    - `dist/index.html` (1.76 kB / 0.71 kB gzip)
    - `dist/assets/index-*.js` (42.26 kB / 13.68 kB gzip)
  - Node.js server-side rendering via `renderToString()` in `src/server.ts` produces complete DOCTYPE HTML documents with zero hydration errors.

## 3. Supported Integration Modes & Documented Alternatives

### Mode A: Model Context Protocol (MCP) — Stdio Server
- **Supported Environments**: Claude Code, Cursor, Windsurf, Gemini CLI (via MCP bridge).
- **Configuration**:
  ```json
  {
    "mcpServers": {
      "samrey": {
        "command": "npx",
        "args": ["-y", "@samrey/mcp-server"]
      }
    }
  }
  ```
- **Capabilities**:
  - 18 tools: `samrey_search_docs`, `samrey_get_api_reference`, `samrey_get_examples`, `samrey_validate_code`, `samrey_analyze_project`, `samrey_diagnose_errors`, etc.
  - 8 resources: `samrey://docs/overview`, `samrey://docs/reactivity`, `samrey://docs/runtime`, `samrey://examples`, etc.
  - 7 prompts: `build-samrey-component`, `build-samrey-dashboard`, `implement-samrey-routing`, etc.

### Mode B: Workspace Rule Files (Zero-Config Context)
- **Supported Environments**: Cursor (`.cursor/rules/samrey.mdc`), GitHub Copilot (`.github/copilot-instructions.md`), Claude Project (`CLAUDE.md`), Gemini (`GEMINI.md`).
- **Capabilities**:
  - Automatic activation based on file glob pattern (`**/*.{ts,tsx,js,jsx}`).
  - Prohibits foreign hooks and enforces immutable signal state mutations.

### Mode C: Portable Agent Skills (`skills/`)
- **Supported Environments**: OpenAI Codex, Windsurf, AutoGPT, Dev-Agent, Claude Code CLI.
- **Capabilities**:
  - 10 structured Markdown skills conforming to Agent Skills Standard:
    1. `samrey-overview`
    2. `samrey-project-creation`
    3. `samrey-components`
    4. `samrey-reactivity`
    5. `samrey-routing`
    6. `samrey-http`
    7. `samrey-forms`
    8. `samrey-ssr`
    9. `samrey-testing`
    10. `samrey-debugging`

### Mode D: Command-Line Interface (`@samrey/cli ai`)
- **Supported Environments**: Any terminal-capable AI agent or developer workflow.
- **Commands**:
  - `samrey ai init`: Scaffold instructions, skills, and `.cursor/mcp.json`.
  - `samrey ai doctor`: Verify project health score (0-100) and scan for anti-patterns.
  - `samrey ai docs <query>`: Instant offline terminal documentation lookup.
  - `samrey ai validate <file>`: Validate component syntax and compiler correctness.
  - `samrey ai skills --install`: Install portable skills into project directory.
