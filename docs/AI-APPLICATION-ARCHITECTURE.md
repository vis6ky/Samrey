# Samrey Framework — AI Application Architecture Guide

> **Authority**: Architectural design principles, component topologies, and state patterns for AI agents building production applications in Samrey.

---

## 1. Architectural Philosophy: The Zero-VDOM Paradigm

Samrey applications execute with **zero Virtual DOM**. Unlike React, Vue, or Angular:
- **Components Run Once**: Component functions execute exactly once during instantiation. They are factory functions that construct and wire the DOM tree, not render functions that re-execute on every state tick.
- **Static Template Hoisting**: Markup invariants are hoisted at module scope using `template('...')`. Cloning pre-parsed template fragments leverages native browser C++ `cloneNode(true)`, outperforming synthetic element construction by an order of magnitude.
- **Surgical Reactivity**: Fine-grained reactive signals (`signal()`, `computed()`) connect directly to micro-DOM mutation points (`bindText`, `bindAttr`, `bindClass`, `on`). State updates bypass component trees entirely and touch only the target DOM nodes.

## 2. Canonical Application Topologies

### Topology 1: Authenticated SaaS Shell

```
┌────────────────────────────────────────────────────────┐
│                      App Shell                         │
│  ┌───────────────┐  ┌────────────────────────────────┐ │
│  │               │  │             Header             │ │
│  │               │  ├────────────────────────────────┤ │
│  │               │  │                                │ │
│  │    Sidebar    │  │       RouterOutlet()           │ │
│  │   Navigation  │  │   (Dashboard, Users, Analytics)│ │
│  │    (Link())   │  │                                │ │
│  │               │  ├────────────────────────────────┤ │
│  │               │  │       NotificationCenter       │ │
│  └───────────────┘  └────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

1. **Root `App`**: Mounts invariant structure once (`sidebarMount`, `headerMount`, `mainOutlet`, `notificationMount`).
2. **Route Protection**: Wrap the `RouterOutlet()` inside `Show({ when: () => isAuthenticated.value, children: () => RouterOutlet(), fallback: () => LoginView() })`.
3. **Reactive Breadcrumbs**: Drive active navigation items and page headers directly from `router.currentPath`.

## 3. State Management Patterns

### Domain-Partitioned Signals
Organize reactive state into clear domain boundaries:
- **Auth Domain**: `currentUser = signal<User | null>(...)`, `isAuthenticated = computed(() => currentUser.value !== null)`.
- **UI Domain**: `isSidebarOpen = signal<boolean>(true)`, `activeTheme = signal<'light' | 'dark'>('light')`.
- **Data Domain**: `users = signal<User[]>([])`, `searchQuery = signal<string>('')`, `filteredUsers = computed(...)`.

### Batching High-Frequency Mutations
When multiple state mutations happen concurrently (e.g. bulk data load or multi-field resets):
```ts
import { batch } from '@samrey/reactivity';

batch(() => {
  users.value = loadedUsers;
  searchQuery.value = '';
  isLoading.value = false;
  // Subscribers notify exactly once at the conclusion of the batch
});
```

## 4. Component Construction Standard

Every Samrey component generated by an AI agent must follow this structure:

```ts
import { signal } from '@samrey/reactivity';
import { template, on, bindText } from '@samrey/runtime';

export interface CardProps {
  initialTitle?: string;
}

// 1. Module-Scoped Static Template Hoisting with Template References
const _tmpl = template(`
  <div class="card">
    <h3 ref="title"></h3>
    <button ref="btn">Click me</button>
  </div>
`);

export function Card(props?: CardProps): HTMLElement {
  // 2. Fine-Grained Reactive State
  const clicks = signal(0);

  // 3. Clone Static Fragment & Extract References
  const root = _tmpl.clone();
  const { title, btn } = root.refs;

  // 4. Surgical DOM Bindings
  bindText(title, () => `${props?.initialTitle ?? 'Card'}: ${clicks.value}`);

  // 5. Native Event Listener
  on(btn, 'click', () => clicks.update(n => n + 1));

  // 6. Return Cloned Root Node
  return root;
}
```

## 5. Security & Contextual Sanitization

All dynamic user-controlled inputs must be contextualized:
- **Text content**: Always use `bindText()`, which writes safely to native `textContent` and is immune to XSS.
- **HTML injection**: Never assign raw `innerHTML`. Use `sanitizeHtml()` from `@samrey/security` and register with `TrustedTypesPolicy`.
- **URIs**: Dynamic URLs must be sanitized via `sanitizeUri()`.
- **Forms**: Implement CSRF tokens via `createCsrfToken()` and pair accessible form inputs with `role="alert"` validation spans.
